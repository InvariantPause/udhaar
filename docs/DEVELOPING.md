# Developing Udhaar

The app lives in `mobile/` — React Native + Expo (SDK 57), TypeScript, expo-router,
expo-sqlite. Feature conventions and data-layer invariants live in
[`AGENTS.md`](../AGENTS.md); read that first.

## Toolchain

- Node + npm, JDK 17 (`brew install openjdk@17`), Android command-line tools
  (`brew install android-commandlinetools`).
- A phone or emulator running the **dev build** — Expo Go cannot load the app
  (`react-native-keyboard-controller` is a native module).

## Commands

| Command | What it does |
|---|---|
| `npx expo start` | Start Metro; connect the installed dev build to the printed URL |
| `npm run apk` | Build the dev-build APK → `android/app/build/outputs/apk/debug/app-debug.apk` |
| `npm run apk:release` | Standalone release APK → `release/udhaar-<version>.apk` |
| `npx tsc --noEmit` | Typecheck |
| `npm run lint` | Lint |
| `npm run db-check` | Replay the real schema + money invariants on `node:sqlite` |

## Layout

- `mobile/src/app` — expo-router screens (typed routes)
- `mobile/src/features` — sheets and feature components
- `mobile/src/lib/db` — schema, migrations, repo (the source of truth; balances are
  computed by SQL views, never stored)
- `mobile/src/design` — tokens (pure mono, dark-first)
- `mobile/scripts` — db-check and APK build scripts
- `mobile/plugins` — config plugins that survive `prebuild`

## Native folders

`mobile/android/` is generated by `npx expo prebuild` and gitignored. Never edit it
by hand — put changes in `app.json` or a plugin in `mobile/plugins/`.

## Release signing

Release builds are signed with a private keystore that lives **outside** the repo:

- Keystore: `~/keystores/udhaar-release.keystore` (back it up — if it's lost, no
  future update can ever install over the app again)
- Path + passwords in `~/.gradle/gradle.properties` as `UDHAAR_RELEASE_*`
- `mobile/plugins/withReleaseSigning.js` wires them into `android/app/build.gradle`
  on every prebuild
- `scripts/build-release.sh` refuses to build unless the key is configured

A fresh clone without those properties still builds — release falls back to the
debug key locally. Never ship an APK signed that way.

## Permissions and backup

The manifest deliberately keeps only what the app uses: `SYSTEM_ALERT_WINDOW` and
legacy storage permissions are blocked in `app.json` (`android.blockedPermissions`).
`INTERNET` stays because dev builds need Metro; the app itself makes no network
calls. Android auto-backup is off (`android.allowBackup: false`) — the app's JSON
export is the backup path.

## Checking your work

There is no test runner. `npm run db-check` is the safety net for the data layer —
run it after any schema/repo/backup-format change. Typecheck and lint before
committing.
